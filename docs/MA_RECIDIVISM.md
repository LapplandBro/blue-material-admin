# MA Recidivism

Плагин считает **очки рецидива** по игроку и, если очки доходят до порога, может выдать постоянное наказание. По умолчанию он только считает (`dry_run`) и в чат админам пишет текущие очки. База — та же, что у Material Admin. Таблицы `sb_recid_*` плагин создаёт сам.

Строка в чат уходит админам с флагом `b` (доступ к `sm_history`), если включён `ma_recidivism_notify_admins`. Её пишет каждое засчитанное наказание и команда `sm_history`.

## Строка в чате

```
[Recidivism] imbeatingyou_ — Ban 0.0/12 | Gag 0.0/12 | Mute 0.0/12
```

Это **не** лимит «сколько наказаний можно выдать» и **не** счётчик банов.

Три числа — очки рецидива по трём веткам: **сейчас набрано / порог**. Формат: один знак после запятой у очков, порог целым.

- `0.0` — по этой ветке очков сейчас нет.
- `12` — порог ветки. По умолчанию 12 у всех трёх: `ma_recidivism_threshold_ban`, `ma_recidivism_threshold_gag`, `ma_recidivism_threshold_mute`.

Когда очки ветки доходят до её порога, ветка уходит в постоянное наказание (если `dry_run` выключен, см. ниже):

- Ban — автоперм бана (режим `perm`);
- Gag — автоперм гага;
- Mute — пермамут.

Следом может прийти вторая строка. При пороге 12 «близко» начинается с 9.0 (75%):

- `Ban у nick близко к порогу: 9.0/12` — ещё не порог;
- `⚠ Ban у nick: 12.0/12 → автоперм` — порог взят, автобан ещё не отмечен;
- `⚠ Ban у nick: 12.0/12 (уже перм)` — ветка уже помечена как эскалированная;
- для Gag текст тот же (`→ автоперм`), для Mute — `→ пермамут`.

Для предупреждения и для автонаказания берётся **большее** из очков этого аккаунта и «семья max» по той же ветке. В короткой строке выше семьи нет: показаны только очки этого SteamID.

Если отпечатков больше одного, строка длиннее:

```
[Recidivism] nick — Ban 1.5/12 | Gag 0.0/12 | Mute 0.0/12 (семья max 4.0/0.0/0.0, 3 акк.)
```

`Ban 1.5/12` — очки **этого** аккаунта. `семья max 4.0/0.0/0.0` — максимум очков Ban / Gag / Mute среди связанных аккаунтов (не сумма). `3 акк.` — сколько SteamID в этой семье. В меню у ветки, где чужой аккаунт выше, будет `(max …)`. Звёздочка `*` в меню — ветка уже эскалирована.

## Три ветки

| Ветка | Откуда событие в Material Admin |
| --- | --- |
| `ban` | бан и добавление бана |
| `gag` | мут чата |
| `mute` | мут голоса |

Сайленс (чат и голос вместе) — это **два** события: одно в `gag`, одно в `mute`. Причина с меткой `[AUTO]` плагин не считает повторно: так он не накручивает очки на собственную эскалацию.

Снятие бана / гага / мута / сайленса (при `ma_recidivism_revoke_on_unpunish 1`) отзывает **последнее** неотменённое событие этой ветки и пересчитывает очки. В чат: `Сняты очки [ban] с STEAM_…`.

## Откуда очки

Очки копятся из событий в скользящем окне `ma_recidivism_window_days` (по умолчанию 30 суток). Отозванные события в сумму не входят.

Сырой вес зависит только от длины наказания, в минутах, как его отдаёт Material Admin (`PointsRawFor`):

- срок `0` или меньше (пермач) — **0.0** очков, ветка помечается «уже перм», автоэскалация из-за этого события не запускается;
- бан до 1 суток включительно (`<= 1440` мин) — **3.0**;
- бан 2–7 суток (`<= 10080` мин) — **4.0**;
- временный бан длиннее 7 суток — **5.0**;
- гаг или мут до 60 минут включительно — **2.0**;
- гаг или мут длиннее 60 минут — **3.0**.

Наказания одного SteamID, выданные в пределах `ma_recidivism_incident_sec` (по умолчанию 900 секунд), склеиваются в один инцидент. К сырому весу применяется множитель инцидента:

- первое наказание инцидента — `ma_recidivism_mult_primary` **1.0**;
- в инциденте уже есть другая ветка — `ma_recidivism_mult_secondary` **0.5**;
- в инциденте уже есть эта же ветка — `ma_recidivism_mult_same_track` **0.25**;
- сайленс (каждое из двух событий) — `ma_recidivism_silence_split` **0.6**, вместо трёх множителей выше.

Итог ветки — сумма по событиям окна: `сырой вес × множитель инцидента × вес давности`. При `ma_recidivism_decay 1` вес давности линейный: у свежего события 1, к концу окна падает к 0. При `decay 0` вес давности всегда 1. Поэтому на экране может быть `2.4`, а не целое.

`ma_recidivism_require_same_admin` в конфиге есть (по умолчанию 0), но плагин записывает id админа как 0 и фильтр «тот же админ» фактически не включает.

Боты и `STEAM_ID_LAN` не учитываются.

### Семья отпечатков

Если в `databases.cfg` есть подключение `rebanner` и в нём находится строка `rebanner_fingerprints`, плагин берёт список SteamID из поля `steamid2` (через `;`). Это семья альтов по отпечатку: сам игрок плюс связанные, не больше 24 аккаунтов, кэш около 60 секунд.

`семья max` по ветке — `MAX(score)` среди этих аккаунтов, не сумма. Нет базы `rebanner` — семьи нет, в чате короткая строка, порог смотрит только на этот аккаунт. В лог сервера: `rebanner DB unavailable … family-max disabled`.

## Порог и dry_run

Порог сравнивается с максимумом из очков аккаунта и семьи по этой ветке. Ветка, которая уже эскалирована, повторно не наказывается.

`ma_recidivism_dry_run` по умолчанию **1**: очки пишутся, чат пишется, наказание **не** выдаётся. При достижении порога админы видят: `DRY-RUN порог [ban] для STEAM_… (12.0) — автодействие не выдано`. В меню заголовок с `[dry]`.

`dry_run 0` — при пороге плагин сам наказывает от имени сервера, причина вида `[AUTO] автоэскалация ban (12.0 / 30д)`:

- бан, `ma_recidivism_escalate_mode perm` (по умолчанию) — бан на 0 минут, то есть пермач;
- бан, режим `lock` — бан на `escalate_min_ban_minutes` из таблицы конфига (сид **10080** минут, 7 суток); отдельного cvar на это число нет;
- гаг — постоянный гаг (0 минут);
- мут — постоянный мут голоса (0 минут).

Режим `lock` меняет только бан. Гаг и мут при эскалации всегда постоянные.

## Команды

Нужен флаг `b`, кроме двух команд с пометкой root (флаг `z`).

| Команда | Что делает |
| --- | --- |
| `sm_history`, `sm_recidivism` | Очки игрока. Без аргумента — меню целей. Иначе ник или `STEAM_…`. |
| `sm_recidlist`, `sm_recidivism_list` | Топ-20 по сумме трёх веток. Только из игры. `*` перед ником — какая-то ветка уже эскалирована. |
| `sm_recid_reload` | Root. Заново читает `sb_recid_config`. |
| `sm_recidivism_reset <ник\|STEAM_>` | Root. Отзывает все события этого SteamID и обнуляет очки. |

В `sm_admin` пункт Material Admin: «Рецидив: игрок / история» и «Рецидив: список (топ)».

`sm_recid_reload` после чтения таблицы сразу накладывает текущие cvar. Значения из `cfg/sourcemod/ma_recidivism.cfg` и живые cvar перекрывают одноимённые ключи таблицы. Правка только строки в `sb_recid_config` не удержится, пока тот же параметр висит в cvar.

## Главные cvar

Файл: `cfg/sourcemod/ma_recidivism.cfg`. Выключить учёт целиком: `ma_recidivism_enable 0`.

| Cvar | По умолчанию | Смысл |
| --- | --- | --- |
| `ma_recidivism_enable` | 1 | Вести учёт |
| `ma_recidivism_window_days` | 30 | Окно, в котором события дают очки (1–365) |
| `ma_recidivism_incident_sec` | 900 | Окно склейки наказаний в один инцидент, секунды |
| `ma_recidivism_mult_primary` | 1.0 | Множитель первого наказания инцидента |
| `ma_recidivism_mult_secondary` | 0.5 | Множитель другой ветки в том же инциденте |
| `ma_recidivism_mult_same_track` | 0.25 | Множитель повтора той же ветки в инциденте |
| `ma_recidivism_silence_split` | 0.6 | Множитель каждого события сайленса |
| `ma_recidivism_threshold_ban` | 12 | Порог ветки бана |
| `ma_recidivism_threshold_gag` | 12 | Порог ветки гага |
| `ma_recidivism_threshold_mute` | 12 | Порог ветки мута |
| `ma_recidivism_dry_run` | 1 | 1 — только счёт и чат, без автонаказания |
| `ma_recidivism_revoke_on_unpunish` | 1 | Снятие наказания снимает очки последнего события ветки |
| `ma_recidivism_decay` | 1 | Линейное затухание внутри окна |
| `ma_recidivism_escalate_mode` | perm | Эскалация бана: `perm` или `lock` |
| `ma_recidivism_notify_admins` | 1 | Писать строки `[Recidivism]` админам |
| `ma_recidivism_require_same_admin` | 0 | Задуман как фильтр инцидента по админу; сейчас не работает, id админа не заполняется |

## Таблицы

`sb_recid_config` — пары ключ/значение (окно, пороги, множители, `dry_run`, `decay_enabled`, `escalate_mode_ban`, `escalate_min_ban_minutes`). `sb_recid_incidents` — группа наказаний одного SteamID внутри окна инцидента: ник, основная ветка, время открытия. `sb_recid_events` — журнал каждого наказания: ветка, сырые очки, множитель инцидента, источник (`ban` / `gag` / `mute` / `silence` / `auto_escalate` и др.), длина, причина, флаг отзыва. `sb_recid_scores` — кэш очков на пару SteamID+ветка (`score`, сколько активных событий, флаг `escalated`); именно отсюда чат берёт `0.0/12`.
