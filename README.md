# Blue Material Admin

Веб-панель для игровых серверов Source: **CS:GO, CS2, TF2** и соседние игры. С её помощью смотрят баны и муты, выдают админку, дергают RCON, принимают жалобы.

Это **свой форк** [SourceBans](https://github.com/GameConnect/sourcebansv1) / [SourceBans++](https://github.com/sbpp/sourcebans-pp). Лицензия — [GNU GPLv3](LICENSE). Тема одна: **Blue V2**, тёмная. Переключить её в настройках нельзя — так и задумано, иначе ломается вёрстка.

Идея «материальной» панели выросла из публичного рефорка на [HLMod](https://hlmod.net/threads/alpha-material-admin-refork-na-osnove-sb-1-5-4-7-bootstrap-3.36382/) — это дань той работе. Дальше сборка живёт отдельно, не как продолжение чужих Material Admin.

Эта ветка — **`php-8.3`**: PHP **8.3** (минимум **8.2**). Если хостинг ещё на **PHP 7.1**, бери ветку [`main`](https://github.com/LapplandBro/blue-material-admin/tree/main).

Версия панели сейчас **2.1.0**.

## Что умеет панель

- списки банов, мутов и админов, онлайн серверов  
- кик и бан из мониторинга, веб-RCON  
- админы, группы, флаги SourceMod, overrides  
- протесты и предложения банов, свои причины  
- уведомления, системный лог, почта  
- SEO: карта сайта, robots, картинка для шаринга  
- антифрод по связанным аккаунтам (PARSEC)  
- ваучеры — одноразовый ключ на админку  
- бан Steam-группы и друзей: по желанию без ников, сразу steamid64 из XML  
- установщик с проверкой хостинга  

Рядом лежат исходники плагинов SourceMod: папка [`sourcemod/`](sourcemod/). Там ядро Material Admin и стек PARSEC для TF2 (передача файла, проверка клиента, повторный бан твинков).

## Установка

Нужны PHP, MySQL/MariaDB и права на запись в пару каталогов. Полный список — в [`requirements.txt`](requirements.txt).

1. Залей файлы в корень сайта.  
2. Создай пустую базу.  
3. Открой `/install/` и пройди мастер.  
4. Удали папку `install/` (на последнем шаге есть кнопка).  
5. В `config.php` при желании пропиши ключ Steam API и защищённые SteamID.

Проверка без браузера:

```bash
php install/dry_run.php
```

## Как обновлять файлы

Встроенный «updater» не используем — он чаще путает, чем помогает. Копируй файлы руками.

Сначала бэкап: `config.php`, `data/`, демки, свои картинки карт и лого, дамп базы. Без бэкапа претензии «ничего не работает» бессмысленны.

Скачай ZIP с ветки `php-8.3`, распакуй **на компьютере**, не сразу на живой сайт.

**Не затирай:** `config.php`, `data/`, `demos/`, свои карты и обложки. Папку `install/` на рабочий сайт не заливай и установщик повторно не гоняй.

**Можно заменить:** `includes/`, `pages/`, `scripts/`, `themes/blue_v2/`, иконки, страницы ошибок, корневые PHP **кроме** `config.php`. `.htaccess` трогай, только если сам его не правил.

После заливки — жёсткое обновление страницы (Ctrl+F5). Белый экран: смотри лог PHP и не стёр ли `config.php`. Обычное обновление **без SQL**. Миграции базы бывают только если это явно написано в релизе.

Если сайт стоит за Caddy, а PHP крутит Apache — ЧПУ настраивается на Apache, не в Caddy. Иначе будет петля редиректов. Подробности: [`docs/CADDY.md`](docs/CADDY.md).

## Ваучеры

Одноразовый ключ, по которому гость сам создаёт аккаунт админа. Включается в настройках. Выпускает ключи только владелец панели. Активировать может **только незалогиненный** человек — иначе получится второй аккаунт поверх уже существующего.

Ключ — 32 hex-символа (можно с дефисами). Старые «16 цифр» из прошлых сборок больше не принимаются: перевыпусти ключ.

Магазин или бот могут выпускать ключи через `api/voucher_create.php`. По умолчанию API выключен: нужен токен в `config.php`. Тестер есть в админке, в разделе ваучеров.

## Безопасность (что уже закрыто)

Формы, которые что-то меняют, ходят с CSRF. Пароли — bcrypt, старый sha1 при входе сам переезжает. Сессия с нормальными флагами cookie. Демки отдаются только через `getdemo.php`. RCON проверяет права и привязку к серверу.

Если кто-то пытается забанить админа панели по SteamID или защищённый аккаунт из `SB_PROTECTED_STEAMIDS` — бан отменяется, у атакующего снимают права, в лог пишется превышение полномочий. То же при бане человека с более высоким иммунитетом.

По дороге закрыты типичные дыры: подмена Host в письмах и RCON, обход прав, SQL-инъекции, XSS через имя сервера, загрузка файлов, debug-SQL из ADOdb. В логах пароли не светятся.
